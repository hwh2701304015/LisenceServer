# AmazeMend License Server

This service is intentionally small and portable. It can run on Cloudflare
Workers with D1 today, and the API/database contract can be moved to a normal
server later without changing the desktop client.

## Product Rules

- One license key can bind to one device only.
- Supported plans: `monthly`, `yearly`, `lifetime`.
- Free users can repair and preview. Export/save is license gated in the
  desktop client.
- Device support starts with Windows and leaves room for macOS by using a
  platform-neutral device fingerprint generated by the client.

## API

`POST /v1/licenses/activate`

```json
{
  "licenseKey": "AMZ-....",
  "device": {
    "fingerprint": "sha256-hex",
    "platform": "windows",
    "machineName": "optional",
    "appVersion": "1.0.0"
  }
}
```

Successful response:

```json
{
  "ok": true,
  "status": "active",
  "plan": "monthly",
  "expiresAt": "2026-11-04T00:00:00.000Z",
  "bound": true,
  "serverTime": "2026-10-04T00:00:00.000Z"
}
```

Common errors are `invalid_license`, `license_disabled`, `license_expired`,
`device_limit_reached`, and `bad_request`.

### `POST /v1/admin/licenses`

Protected by `Authorization: Bearer <LICENSE_ADMIN_TOKEN>`. Use this from a
payment webhook or an internal order tool.

```json
{
  "plan": "yearly",
  "orderId": "paddle-order-id",
  "customerEmail": "buyer@example.com"
}
```

The server generates a license key and calculates expiry from the plan unless
`expiresAt` is provided.

### `POST /v1/webhooks/paddle`

Paddle calls this endpoint after checkout events. The server verifies
`Paddle-Signature`, processes only `transaction.completed`, maps the Paddle
price/custom data to a license plan, creates the license, then sends the key by
email.

Required environment variables:

```text
PADDLE_WEBHOOK_SECRET=...
PADDLE_PRICE_MONTHLY=pri_...
PADDLE_PRICE_YEARLY=pri_...
PADDLE_PRICE_LIFETIME=pri_...
RESEND_API_KEY=...
MAIL_FROM=AmazeMend <license@amazemend.com>
```

`webhook_events` stores processed Paddle event ids so retries do not create
duplicate licenses. A failed email send is not marked processed, so Paddle can
retry and the same `order_id` will reuse the existing license.

## Concurrency

Activation is a single conditional write:

1. Insert a binding for the license if none exists.
2. If the binding already exists, update only when the incoming device
   fingerprint is the same.
3. Return no row when another device already won the binding.

A unique index on `activations.license_id` enforces the one-device rule at the
database layer, so simultaneous registrations do not rely on application memory
or a fragile `SELECT then INSERT` flow.

## Cloudflare Deploy

```powershell
wrangler secret put LICENSE_TOKEN_SECRET
wrangler secret put LICENSE_ADMIN_TOKEN
wrangler d1 execute amazemend-license --file ./schema.sql
npm install
npm run deploy
```

If an older local or D1 database was already created with the retired
`quarterly` plan, run:

```powershell
wrangler d1 execute amazemend-license --file ./migrations/001_quarterly_to_yearly.sql
```

For existing databases created before Paddle webhooks, run:

```powershell
wrangler d1 execute amazemend-license --file ./migrations/002_paddle_webhooks.sql
```

## Migration Notes

The client only depends on the HTTPS JSON API. When moving away from
Cloudflare, keep the same endpoints and preserve the conditional binding:

- PostgreSQL: `INSERT ... ON CONFLICT (license_id) DO UPDATE ... WHERE`.
- MySQL: use a transaction and a unique key on `license_id`.
- Keep activation in the primary SQL database; telemetry can be queued.
